## 按新标准是否完整

**就分析本次研究的三家方法、回顾 dev-skills 优化过程而言，核心资料足够，且这些核心内容已经在远端。** 不再以个人运行数据是否齐全判断该目标。

证据：

- [工业级交付来源索引](../research/agent-delivery-2026-09-28/sources.md)对应的 75 条 manifest 项均能在远端快照找到，全部 SHA-256 匹配；其中 3 条明确标为不可用正文，不把它们算作有效理论依据。
- Lauren 的固定 pstack 源码快照含 158 个文件，访谈、字幕和相关理论稿已跟踪，视频原件不影响文字层面的分析。
- [三家综合](../research/skills-consistency-2026-10-01/README.md)、[理论新内容核对](../research/skills-consistency-2026-10-01/vendor-latest.md)、[流程演进 v0.32](../process/complex-requirement-delivery.md)、[讨论索引](README.md)能串起理论、问题、方案、用户决定和落地结果。
- 对远端快照中 132 份非原始资料、非验收输出的 Markdown 做相对文件链接检查，未发现目标文件缺失。该检查排除了大批原始资料和细节输出，不是对全仓所有链接及锚点的保证。

但仍有三类整理问题：

1. **入口过时。** 根 README 仍以旧研究为主，写着旧流程和多处“未经确认”；讨论索引的部分摘要也停留在早期阶段，正文则已记到 PR #27–#29 合入。读者可能将历史方案当成当前状态。
2. **不是所有引用原文都在本仓库。** `vendor-latest.md` 明确依赖另一个 dev-skills 仓库的 `skills/agent-prompt-rules/references/sources/`。例如 Codex Prompting、Orchestration and handoffs、Anthropic Skill authoring best practices、Claude Code Best practices 的完整原文未在本仓库找到独立快照；引用或其他原文中的链接不等于全文。它们不妨碍阅读已有综合分析，但若要求只 clone 本仓库即可逐条复核全部理论，应补齐或提供固定版本的跨仓入口。
3. **最新实现另有维护源。** dev-skills 的 Skill 源码本来就放在 dev-skills 仓库，本仓库记录优化过程。这符合用户既有分工，不应该为了“完整”复制出第二份维护源；需要的是明确的固定版本入口。

“足够”只针对已研究的开发流程、harness、Skill、prompt 和验证方法，不声称穷尽三家的所有文章与理论。原资料中已有的图片未取到、抓取失败等边界继续有效。

## 敏感信息

**远端确实有敏感业务内容，不能认定为已经脱敏、可以直接公开。** private 是当前访问设置，不代表内容已无敏感信息。

- 公司内部需求正文：例如 `requirements/goal-v2-and-feedback-fixes/source-doc.md` 保存从飞书取回的需求、反馈和内部 MR 上下文。
- 内部项目、工单与实现线索：固定快照中 36 个文本文件出现内部 GitLab 域名，11 个出现飞书链接；还有产品代码路径、验证输出、内部问题与运行标识。计数是字符串命中的文件数，不能当作独立泄露事件数。
- 本机环境与个人记录：230 个文本文件包含本机绝对路径；旧分析、工具输出、数据索引等保留了环境和操作线索。

凭据检查采用 Gitleaks 8.30.1 默认规则，分别扫描远端完整文件快照（含最多两层归档）和 master 可达的 240 个历史提交，报告值全部脱敏。

- 两轮各命中同一公开网页存档的两处字段：`research/agent-delivery-2026-09-28/raw/lauren/interview-public-page.html` 第 342、361 行，分别为 Datadog `clientToken`、Cloudflare beacon `token`。
- 从代码上下文看，这两处来自抓取的第三方网页前端配置，没有证据表明它们是用户的登录凭据或公司 API 密钥；本轮没有调用或验证这些 token 的权限、有效性。
- 没有另外识别出用户私钥、访问令牌或登录凭据。模式扫描不是无遗漏证明，也不能识别所有业务机密；不能据此写“没有敏感信息”。
