结合你已有的资料，这一步需要同时吸收：Lauren 的真实产品操作与观察、Factory 的实现前断言与验证修复、Anthropic 的持久进度和接续记录。

### 1. 验证应该包含什么

| 部分 | 需要证明什么 |
|---|---|
| 需求覆盖 | 每条要求，包括默认值、例外和限制，都有对应检查 |
| 局部规则 | 计算、参数、状态转换等符合要求，通常用单测 |
| 模块协作 | 参数传递、接口、数据及默认启动装配正确，通常用集成检查 |
| 真实用户流程 | 从真实 UI / API / CLI 操作，最终得到要求的结果 |
| 异常与边界 | 与需求相关的取消、失败、重复事件、恢复等行为正确 |
| 回归与工程检查 | 受影响旧功能正常，必要构建、类型检查和测试通过 |
| 验证可信性 | 用例确实执行，能够发现错误，证据对应准备交付的代码和运行实例 |

这些是检查维度，按需求选择合适方法，可以复用已有测试。性能、权限、并发、迁移等有相关要求或风险时，再增加专项检查。

**对你尤其关键的是：实际参数、持久状态、默认装配和最终副作用。** 例如设置页面显示了新值，还要确认真正发出的请求使用了这个值。

### 2. 如何根据需求生成验证

建议分六步，由 Agent 自动完成：

1. **收集完整依据。** 原始需求、后续修正、已确认决定、计划、仓库规则和运行方法，明确当前有效版本。
2. **拆成可判断的要求。** 每条要求分配 ID，写清前提、动作、预期结果和禁止出现的结果。
3. **生成必要场景。** 正常路径、关键例外、受影响旧行为；同时定位真实入口和观察方法。
4. **变成可执行检查。** 绑定具体测试、命令或工具操作，准备隔离数据，确定断言、等待边界、证据与清理方式。
5. **独立检查是否漏项。** 验收 Agent 从原需求检查场景；关键场景用已知错例确认能发现问题，防止空跑或错误实现照样通过。
6. **执行并自动修复。** 验收失败交回实现 owner；修复产生新版本后，重跑受影响场景和必要的组合检查。

例如，假设需求明确要求“后台运行期间修改 Goal，后台结束后使用最新 Goal 继续”：

```text
前提：Goal 为 A，后台任务正在运行
操作：通过真实入口改成 B，然后让后台任务完成
断言：确实继续执行；实际请求使用 B
证据：操作记录、任务状态、实际继续请求
版本：候选提交 + 启动的构建/服务实例
```

如果需求还规定取消后不继续、重复通知不重复执行，就分别增加场景。缺少真实命令、运行环境或判定依据时，保留草案/阻塞状态。

**验收标准依据需求确定。实现 Agent 不能通过删场景、降低断言让结果变绿。**

### 3. 最终交付物是什么

交付一个能执行、能追溯的**验收包**：

| 产物 | 内容 |
|---|---|
| `verification-plan.json` | 需求来源、要求与场景对应关系、操作、断言、运行条件 |
| 测试 / 脚本 / 工具入口 | 可以实际运行的检查，优先复用业务仓库已有能力 |
| `verification-result.json` | 本次版本、逐场景结果、逐需求结论、失败原因和证据引用 |
| `evidence/` 与生成的报告 | 原始日志、响应、必要截图及简短结论 |

这些文件名是建议，尚非 Agent Lord 原生格式。报告由同一份定义和结果生成，避免重复维护清单。

**自动通过条件：所有有效要求均有充分的必需场景，场景实际通过，证据有效且对应交付候选。** 未执行、无法验证、证据过期都保留明确状态；“用例已生成”不能计为通过。

### 4. 放进你现在的 Agent Lord 流程

```text
需求/方案确定 → 生成验收定义 → 实现及局部检查
→ 整合候选代码 → 独立需求验收
                    ↓ 失败
                  自动修复 → 重验
                    ↓ 通过
                 完成交付报告
```

验收与修复应在 `plan-report` 关闭 run **之前**完成。可以提前创建 MR 触发必要检查，最终报告必须对应实际验证的候选。

你当前已有隔离工作区、依赖准备、恢复和 receipt。需要补的是**自动执行与采证，以及依据实际结果决定能否交付**；目前 receipt 的字段校验还不能证明需求已经满足。

环境恢复、常规修复、重验都可以自动推进。遇到无法消除的需求矛盾、缺失产品决定、不可用权限，或修复预算耗尽，才输出具体阻塞。这样能减少人工介入，同时保留未完成事实。

建议第一版选一条曾经遗漏真实入口的需求，走完一次“发现失败 → 自动修复 → 新版本通过”，再把验证过的做法接入 pipeline。
