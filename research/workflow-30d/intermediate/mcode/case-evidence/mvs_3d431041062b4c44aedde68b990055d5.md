## 1. 那个 fork delta 是做什么的

先说它要解决的问题。

沙箱的规则文件（macOS 的 Seatbelt profile）是一张写死的清单：哪些路径能写、哪些不能。问题是**每次命令的工作区都不一样**——你可能在 A 项目，下一秒在 B 项目，各自的 `.git/hooks` 路径完全不同。

上游那个开源 sandbox runtime 本来就想拦 `.git/hooks`（写入 git hook 等于埋一颗延迟炸弹：下次 `git commit` 时它会自动执行）。它的做法是写一条 `**/.git/hooks/**` 这样的通配规则。听起来能盖住所有项目。

但真机验证发现它**没用**——那条规则会被按「宿主进程当前所在目录」解析，等于只盖住了 runtime 自己那个目录，命不中每次调用的真实工作区。

所以 MR!1 在 fork 里加了 `mandatoryDenyWrite` 这个新参数：**每次生成 profile 时，把这次调用真实算出来的 `.git/hooks` 绝对路径塞进去**。不靠通配，靠动态填值。

它还有个讲究的设计：只拦「写/创建/移入」，不拦「删除」。因为如果走普通的 `denyWrite`，会被删除权限的逻辑误解成「这个路径不可删」，从而把本来允许的删除也一起收走。

一句话：**它是为了让「拦 git hook」这件事真的生效而加的一个动态填值通道。** 而你已经决定不拦 git hook 了，所以它在产品侧失去了唯一的用途。

## 2. MR 修的真问题是什么

分两批。

**上一轮（你拍板的四档对齐）**——严格说不是「修 bug」，是执行你的设计决策，但顺带修掉了一个真 bug：那条遗留守卫让**默认工作区的会话在四档下全都起不了 bash**，也就是你最开始遇到的「删不掉文件」。

**这一轮（我审出来的）三个真缺陷：**

第一个，**错误信息不说是哪个路径**。`Invalid commondir` 这种话让人无法判断是仓库的文件出问题还是 runtime 自己的临时目录出问题。这不是理论风险——同一形态的 `Workspace overlaps protected runtimeDataDir` 当初就把我们俩的排查方向带到了完全错误的层。现在每条都带上具体路径和 `fieldPath`。

第三个，**关闭时泄漏一个定时器**。关沙箱时要等在跑的命令收尾，代码用「等命令结束」和「超时」赛跑。命令先结束时，那个超时定时器没被取消，于是 `close()` 都返回了，Node 事件循环还被它吊住整个超时时长。
