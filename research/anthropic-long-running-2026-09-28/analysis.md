# Anthropic 长任务文章：讲了什么，Agent Lord 可以借鉴什么

原文：[Effective harnesses for long-running agents](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)，Justin Young，2025-11-26。本次 2026-09-28 重新读取全文，网页快照保存在 raw/。下文将原文总结与针对用户的建议分开。

## 原文主要内容

问题是任务超过一段会话后，agent 容易留下半成品、丢失进度，或把部分实现误判为全部完成；压缩聊天记录仍不够。

文章采用两个阶段：首次会话准备运行脚本、功能验收清单、进度文件与初始 Git 提交；后续会话读取记录、检查基本功能、完成一个功能、实际验证，再提交代码并更新进度。完成标记必须依据测试；网页功能需从真实浏览器入口检查。两阶段主要是提示不同，并非必须两个不同模型或并发运行。

实验以当时模型和全栈网页应用为主；作者没有确定单 agent 与多 agent 哪种更好。这篇文章不提供并发调度、PR 合入或跨仓依赖的完整方案。

## 针对 Agent Lord 的建议

依据上一轮 [本机源码核查](../agentlord-gaps-2026-09-28/analysis.md)，不是本轮运行实验。

### 1. 区分执行状态和功能状态

Agent Lord 已能保存任务状态、核对提交、记录验证结果。产品是否满足用户要求仍要靠验收。

例如 Goal 需求：新增接口、提交代码，只证明实现有产物。验收还要运行“后台工作时更新 Goal，后台结束后自动继续，并使用更新后的内容”。这只是适合本项目的示例，不是文章原例或对当前 bug 的声明。

建议把现有 acceptance criteria / verification / receipt 关联到少量明确行为：场景、预期结果、实际运行记录、对应版本。复用现有字段和项目测试，不新建一份同义的状态清单。未运行应标为未验证；执行失败、取消和用户接受的例外继续分开。

### 2. 每次接手先做小检查

新 session 或替换执行者先取得原目标、已定决定、当前分支/提交、已有结果和下一步；确认需要的上游代码已经在当前工作区，再运行与待做任务相关的基本检查。

它能回答“从这里继续是否合理”，不要求把全部历史任务重新验证一遍。若发现环境问题或工作区中他人的未提交修改，明确记录并保留，不擅自清理或回滚。

### 3. 大模块内部也分成可验证的小步

保持现有模块 owner，内部按完整行为推进：实现一段 → 检查 → 保存进展 → 继续下一段。避免到 session 结束时，只剩一大块无法说明状态的改动。

这不等于每个小步单独启动一个外部 CLI，也不要求把彼此独立的模块改成串行。跨模块的真实组合检查仍要提前安排；文章的一次一个功能不能替代当前项目的依赖设计。

### 4. 接续记录直接说明下一步

优先复用 Agent Lord journal/receipt 和现有项目记录，提供简短索引：

- 已完成的用户行为及代码版本。
- 实际运行的检查、结果和证据位置。
- 尚未验证、失败和阻塞项。
- 下一步具体动作及必要前提。

记录已完成事实，不用模型的“全部完成”作证据。保留权威原始结果链接，避免只有压缩摘要。突然中断不可能保证干净提交，恢复时仍需核对实际文件与进程状态；复用现有写入保护，不让新旧执行者双写。

### 5. 提供项目可复用的启动与验证入口

优先使用仓库已有脚本、CLI、测试和日志。若缺失，补最少必要命令，让接手者不用重新研究如何启动与操作。脚本名称不必叫 init.sh，进度文件也不必叫 claude-progress.txt。

业务行为由项目维护，Agent Lord 负责派发与记录。纯文档任务遵守用户现有短流程，不因此增加启动应用或等待 CI。

## 建议先验证的一条流程

选择下一项真实行为需求，使用现有 owner 和恢复机制：取得目标/代码/进度 → 跑基本检查 → 完成一个行为 → 真实验证 → 保存提交与下一步 → 更换或继续 session。

观察接手者是否还需要用户解释做到了哪里、能否识别错误基线、是否能检出已知行为错例。先证明这条路径可靠，再判断需要改哪些 Agent Lord 代码。

## 不直接照搬的地方

- 首次初始化是一个阶段，未必需要增加永久的初始化 agent。
- JSON 是作者当时的实验选择，不意味着必须把所有计划改成 JSON。
- 功能清单是验收依据，不能为了通过随意删改；需求确有变更时仍应有明确的修订依据。
- 当时浏览器工具对原生 alert 的限制属于特定工具/版本，不能当作今天所有工具的能力边界。
- 本次没有实施流程改造，也没有测出收益或最佳并发数。
