# 结构示例：尚不可执行

这是一条为解释方案而虚构的需求，不是 Agent Archon 当前产品规范，也没有修改任何真实任务。

## 示例需求

后台任务运行时，用户可以更新 Goal；当前后台任务完成后应自动继续，使用最新 Goal。等待期间用户取消后，不得继续。重复收到同一次后台完成通知，不得重复启动。

## 文件

- `verification-plan.json`：同一份文件保存要求、场景、断言和执行条件，避免手工重复维护 coverage 表。
- `verification-result.json`：尚未执行的结果形状，不含任何 PASS 或虚构证据。

文件中的命令、真实入口、代码版本和异步判定边界都还没有绑定到实际项目，因此 readiness 为 DRAFT。真正生成时，agent 必须通过项目检视填入有效值、试跑工具并独立核对需求，才能改为 READY。它们不是当前 Agent Lord 的原生 schema，不能直接传给 plan-create。

示例说明两层关系：R01 要求“使用最新 Goal”，V01 检查一次更新，V02 检查连续更新；两个必需场景均通过，才能判定本示例中 R01 达标。V03/V04 分别检查取消和重复通知，不能被主流程成功替代。
