# 独立审查处理

日期：2026-09-28（Asia/Shanghai）。对应 [设计](../design.md) 与 [独立审查](independent-review.md)。这是文档审查与源码阅读，不是执行验证结果。

## 已纳入设计

| 审查关注 | 处理位置与结论 |
|---|---|
| 验收可能照抄实现、漏掉原始要求 | 第 2 节固定来源；从需求拆要求；独立检查遗漏与反例 |
| 提交成功或非空 evidence 被误当成需求通过 | 第 3～5 节区分代码、验收结果及 receipt；明确当前 runtime 不校验实际执行 |
| 旧服务、旧证据、跨仓版本不一致 | 第 4 节记录代码、构建、实例与版本组合；变更后判定失效及必要重验 |
| 失败后降低断言、无限重试 | 第 2 节禁止静默降标；分类有界修复；无法解决时保持明确阻塞 |
| 多个验收共享数据互相污染 | 第 2 节声明隔离、资源依赖、并行条件及清理范围 |
| docs-only 与当前硬编码 CI 冲突 | 第 5 节沿用现有 docs 短路径；统一接入需未来改动，不能伪造 CI 结果 |
| 已关闭 run 无法修复、schema 不支持新字段 | 第 5 节将验收放在关闭前；示例不是原生 schema；具体接入需实施验证 |
| 自动通过被理解为自动合并/部署 | 第 5～6 节保持当前任务已授权的交付终点 |

独立审查结论为“未发现阻碍本轮设计交付的问题”。评审后的补充只增加已有资料与设计的对应说明及来源，未把任何待实施能力改成已实现。

## 实施时仍需验证

1. writable 验收 endpoint 的依赖准备可运行，同时执行前后机械核对候选源码及执行器身份，不能只靠提示约束。
2. integrator 提交候选后，真实 operation、claim、require-commit 与合法续跑允许完成修复循环；本轮未试跑。
3. 证据由执行工具捕获；控制器能够拒绝空跑、旧服务、旧证据和不存在的路径；本轮未实现该控制器。

## 示例与检查边界

示例为虚构 Goal 需求，执行器、候选版本和异步边界仍缺失，必须保持 DRAFT / NOT_RUN。本轮文件检查仅验证 JSON、引用、哈希与文档链接，不能证明业务需求满足或新 pipeline 可执行。
