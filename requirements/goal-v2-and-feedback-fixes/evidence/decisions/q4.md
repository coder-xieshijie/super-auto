## 现象（verify S25，最终 head d5bc1acab4，两次都出现）
操作顺序：
1. 发送 `/goal Run the shell command sleep 60 in the foreground, then write p.txt containing ok.`，横幅出现后点暂停。
2. 发送 `What is 3 + 4? Reply with only the number.`。

两次运行里，这条补充消息都没有得到回复 7。模型在这一轮普通对话（不绑定 Goal）里直接接着做已暂停 Goal 的任务：跑 `sleep 60`、写 p.txt、调用 `update_goal`。

产品守住的部分：这一轮没有 turn_bound；Goal 始终是 paused(user_requested)；`update_goal` 被拒（f1 返回 not_a_goal_turn，f2 返回 goal is paused）。

后果：
- f1：步骤 3 读数时，这一轮普通对话还在跑 sleep，输入框显示的是停止按钮，所以 continue-button 为 0，verify 的字面检查点“继续按钮在”不成立。
- f2：步骤 3 的字面检查点都成立，但 p.txt 是在 Goal 暂停期间写出的。

原因：这一轮的请求只带了 2 条消息。第 1 条是首个 Goal Turn 的用户消息，被暂停打断、没有助手回复，里面有 `<archon_internal_context source="goal">Continue working toward the active thread goal…` 和 objective。第 2 条才是补充消息。在 M4（f938e48db1）的一次运行里，同样的 prompt 得到了回复 7，所以这是模型采样的结果。但它说明 R77“暂停时的补充消息按普通对话执行”现在只靠模型自觉。

spec §10 的原文：“Goal 不在 active（paused、blocked、usage_limited、budget_limited）时发送的补充消息按普通对话执行，不恢复 Goal，不修改其状态；横幅保持原来的状态标签和操作。”verify R77、S25。
