## 背景
用户停止一个前台 Turn 时，会话队列会被暂停（user_stop；上游 preview_train 2ed882f7f8 又加了 session_leave，即 TUI `/clear` 和切换会话），前提是暂停时队列里还有待处理项。同一次停止会通过 `pauseActiveGoalForAbort` 把 active 的 Goal 暂停。Goal 已在队列里的 continuation 让这个队列暂停一直保留。之后恢复 Goal 时，新的 continuation 无法被领取，Goal 停在 spec §6 禁止的状态：active、没有 Goal Turn、没有等待原因。完整 v2 host 上的集成测试复现了这个问题。

已在 e71be11629 修复：用户显式恢复 Goal（PATCH active、继续按钮、/goal resume、/retry、blocked 的继续、编辑后保存、提高预算重开）时，先结束该会话的 user-stop 队列暂停，再交出 continuation。

## 决定 D：额度到点自动恢复是否也结束 user-stop 暂停
spec §6 把到点自动恢复列为必须落地的恢复路径。§7（R57）规定，只有在等待期间暂停、编辑、替换、删除或完成 Goal，才会取消到点恢复。`pauseActiveGoalForAbort` 只暂停 active 的 Goal，所以 Goal 为 usage_limited 时，用户停止一个普通 Turn 不会暂停 Goal，“额度恢复后自动继续”仍然有效。
可选做法：
1. 自动恢复也结束 user-stop 暂停（当前实现）。代价：停止时压在队列里的用户自己的消息，会按 FIFO 在 Goal 之前继续执行。手动恢复也有同样的副作用。
2. 自动恢复不结束暂停。Goal 会留在 §6 禁止的状态，除非另加一个等待原因，例如“队列已暂停”，并在界面上显示。

## 决定 E：turn-final-failure 暂停
前台 Turn 最终失败时，队列会以 turn-final-failure 原因暂停（这是既有行为）。如果此时 Goal 的 continuation 在队列里，之后显式恢复 Goal 时，continuation 同样排在暂停的队列后面。
可选做法：
1. 本 MR 只处理 user-stop 和 session_leave 暂停；turn-final-failure 暂停不动，作为已知限制列出（当前实现）。
2. 显式恢复 Goal 时也结束 turn-final-failure 暂停。
3. 不结束暂停，但给 Goal 一个可见的等待原因。

请对 D、E 分别给出选择和理由。如果某个做法放宽了 spec 的验收或违背了 spec 的意图，请明确指出。
